# 모의 통신 왜곡 평가 계획

기준일: 2026-09-05

## 목표 이름

`radio-sim-v1`: 고정 STT 기준선의 모의 통신 왜곡 강건성 및 기권 필요 조건 평가

## 해결하려는 실패 사례

깨끗한 신고 전화에서는 보존되던 물질 표현이 좁은 대역, 코덱 양자화, 소음, 송신 잘림,
클리핑, 낮은 음량, 짧은 끊김에서 사라지거나 존재하지 않는 물질명으로 바뀌는 경우입니다.

## 가설과 기준선

- 가설: 깨끗한 대조군보다 왜곡 조건에서 CER·WER와 물질명 누락이 증가하며, 복합 조건과
  낮은 SNR에서 증가 폭이 가장 큽니다.
- 기준선: 광주에서 고정한 `faster-whisper small·CPU int8·hotword 미사용`입니다.
- 현재 가설 상태: **부분 구현 또는 개발용 데모** — 서울·인천 각 40건의 절차적 왜곡에서
  낮은 SNR의 성능 저하를 관찰했지만 실제 현장 무전에는 검증되지 않았습니다.

## 데이터와 분리

- 입력: AIHub 71768 서울·인천 화재 Validation과 기존 광주 Validation
- 선택: 우선용어 포함 최대 20건과 미포함 최대 20건을 seed 119 고정 해시로 선택
- 학습 사용: 금지
- 모델·threshold 조정: 모의 왜곡 결과를 본 뒤 서울·인천 외부평가 점수에 맞춰 조정 금지
- 파생물: 승인 원본의 제한을 그대로 적용하고 비공개 GCS에만 저장

의도적 층화 표본은 우선용어 Recall과 false insertion을 모두 관찰하기 위한 것으로, 전체
119 신고의 우선용어 출현율이나 지역 분포를 추정하는 표본이 아닙니다.

## 사전 등록한 변형

| 범주 | 조건 |
|---|---|
| 대조군 | clean |
| 대역 | 8kHz, 300–3400Hz |
| 코덱 proxy | 8kHz + 수학적 8-bit μ-law |
| 절차적 소음 | siren·vehicle·wind × SNR 20/10/0dB |
| 송신 잘림 | 시작 300ms, 종료 300ms |
| 파형 손상 | -12dBFS hard clipping, -18dB gain |
| 끊김 | 3×120ms silence dropout |
| 복합 스트레스 | 대역+vehicle/wind SNR10+μ-law+양끝 200ms+2×100ms dropout |

각 파생 레코드에는 변환 파라미터, base/레코드 seed, 원본 member ID,
원본·라벨·산출물 SHA-256, 입출력 sample rate와 길이를 남깁니다. 실행은 새 출력
디렉터리만 허용해 이전 artifact를 덮어쓰지 않습니다.

송신 시작·종료 잘림과 복합 조건은 잘려서 사라진 음성을 deletion으로 점수화하기 위해
원래 참조문을 유지합니다. 따라서 원본 발화 타임스탬프를 파생 음성에 맞춘 새 정렬로
주장하지 않고 manifest의 `reference_timing`을 `not_applicable`로 기록합니다. 나머지
조건도 사람이 다시 정렬하지 않았으므로 `not_evaluated`입니다.

## 지표와 안전 지표

- CER·WER·RTF 및 clean 대비 레코드 단위 변화
- 우선용어 Precision·Recall·F1·false insertion
- STT→Parser 물질명 Recall
- STT→Resolver Top-1·Top-3, coverage, selective accuracy, 기권율
- 잘못된 단일 CAS 승격 건수

안전 게이트는 잘못된 단일 CAS 승격 0건입니다. 왜곡에서 후보 품질이 낮아질 때는 자동
확정이 아니라 불확실성 보존·재확인·기권으로 이어져야 합니다.

## 채택·기각 조건

- 하네스 채택: 동일 입력·seed에서 archive hash가 재현되고 모든 provenance 필드와
  원본 manifest 결합 검사가 통과할 때
- 기준선 조건부 채택: 단일 왜곡 조건에서 우선용어 F1과 downstream 안전 지표가 서비스
  허용 범위에 있고 잘못된 단일 CAS 승격이 0건일 때
- LoRA 진행: 두 지역 이상에서 동일 오류 유형이 반복되고 clean·왜곡 모두 개선할 수 있는
  학습 가설이 생길 때만
- 중단: source hash 불일치, 개인정보 노출, 평가셋 튜닝 사용, 70,000원 초과 가능성,
  잘못된 CAS 자동확정 발생

수치 임계값은 서울·인천 데이터 구성을 확인하기 전에 임의로 만들지 않습니다. 대신 clean
대비 paired 변화와 0건이어야 하는 안전 불변식을 우선 판정합니다.

## 예상 컴퓨팅 비용

40건×18조건 상한을 지역별로 적용합니다. 파생 생성은 로컬 CPU 우선이며, STT는 기존
Cloud Run Job을 재사용하고 재시도 0·단일 task·실행시간 상한을 둡니다. 실제 선택 음성
시간으로 실행 전 비용을 다시 계산하며 추가 비용 총액 70,000원을 넘을 가능성이 있으면
실행하지 않습니다.

## 주장 범위

말할 수 있는 것은 AIHub 신고 전화에서 절차적으로 만든 특정 왜곡 조건에 대한 오프라인
강건성입니다. 실제 현장 무전 성능, 특정 제조사 무전기·코덱 성능, 화재현장 안전성,
전국 일반화는 주장할 수 없습니다.

## 사실 상태

| 항목 | 상태 |
|---|---|
| 변형 프로필·seed·해시·private ledger 생성 코드 | 구현 완료 |
| synthetic fixture 재현성·원본 결합·덮어쓰기 거부 테스트 | 구현 완료 |
| 서울·인천 승인 원본 파생 실행 | 구현 완료 — 각 40건×18조건, 비공개 GCS |
| 왜곡별 STT 및 downstream 평가 | 부분 구현 또는 개발용 데모 — 실행 완료, CAS 정답 없음 |
| 제한 Whisper LoRA | 부분 구현 또는 개발용 데모 — 별도 광주 Training 실험 진행 중 |
| 실제 현장 무전 강건성 | 검증되지 않은 가설 |

파생 run summary SHA-256은 인천
`7d13e888f8ca40b0c43d728666593d55c6ff11c5f6bc813f403819b4d2480c78`, 서울
`59667688aa1b25fac842d5b8b20abf8558ca4254272d7174d70135bfca72aae8`입니다. 두 지역 모두
40건×18조건 STT 실행을 완료했고, 분리된 downstream 평가에서 후보 자동 승격·2-CAS Gate
우회·확인 전 위험 출력·Rule 조기 실행은 0건이었습니다. 이는 CAS 사람 정답 정확도나 실제
현장 안전성을 증명하지 않습니다.

두 지역의 `wind_snr0`에서 공개 우선용어 `연기` 누락이 반복돼 제한 LoRA **실험 설계**
조건을 충족했습니다. 서울·인천 결과를 이 설계에 사용했으므로 두 지역을 LoRA의 최종
비공개 test로 다시 주장하지 않습니다.
